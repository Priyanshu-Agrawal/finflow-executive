### 8.3 The ten rules (summary; full text in the design doc)
1. One navigation from one list. **Names: Home, Ledger, Excel, Loans, Splits, plus Budget** (own page, replaces Home's "Budget Burn" tab); URLs unchanged (`/expenses` label "Ledger", `/ledger` label "Splits"); phone bottom bar Home/Ledger/Excel/Loans (+ More). 2. One page frame (short `h1` = nav label, optional one-line description hidden on phone, actions on the right, sticky control bar, no second title). 3. Sticky top bar, control bar and every table header. 4. One floating Today button on Ledger and Excel (anchor at 30%). 5. One type system: sans for everything; serif only wordmark + Home hero balance; mono only Excel grid/formula bar/row numbers; no wide-tracked caps; text >= 12 px. 6. ## 11. Pitfalls and gotchas (each cost time on 12 Nov)
1. **Wrong Node** (default 20): run `nvm use 22` first; otherwise the new Google packages may misbehave and `npm` warns.
2. **Sheets read quota 429** (section 4.7). A failing prod endpoint during testing is usually this, not a bug.
3. **Next rewrites `tsconfig.json`** when `NEXT_DIST_DIR` is set; run `git checkout tsconfig.json`. Stale generated types under `.next/types` or `.next/dev/types` can produce phantom type errors after switching branches: `rm -rf .next/types .next/dev`.
4. **Never `pkill` by pattern** (`pkill -f next-server` can kill the live :3000 server). Kill by exact PID: `kill $(lsof -tiTCP:PORT -sTCP:LISTEN)`.
5. **Removing a package breaks the running :3000 server** if its old build loads it at runtime (happened with `googleapis`): rebuild and restart :3000 after dependency changes.
6. **zsh/macOS quirks:** quote globs (`--include='*.tsx'`); BSD `sed -i ''` fails on some patterns (use Python or the Edit tool); `$var` is not word-split in zsh loops.
7. **Playwright:** run scripts as `.ts` through `npx tsx`, but browser-side functions passed to `page.evaluate` break under tsx (`__name is not defined`): write audit scripts as plain `.cjs`. `ctx.setOffline(true)` does not take the service worker's own fetches offline reliably; the offline page was verified by navigating after setting offline. Use `page.waitForResponse` set up **before** `goto`. `isVisible()` does not wait.
8. **The dev server (`next dev`) caused HMR reload loops and read floods**; use production builds on a separate `NEXT_DIST_DIR` and port.
9. **`GENERAL_EXPENSE_PATTERN` matches "grocery" but not "groceries" or "auto"**, so such rows are not counted as general spending (app and the sheet's cycle-total formula). Board card "Groceries is not counted as general spending" (owner decision; changing it moves safe-spend and Row 247).
10. **Service worker scope:** it lives at `/sw.js` (root scope) and must keep `Service-Worker-Allowed: /` and `no-cache`; never cache `/api/*` or `/login`; offline page `/offline.html` must stay public in `middleware.ts`.
11. The old UI's `useFinancials` default `budgetRecurringDay` is 6 (Home passes 7): pages other than Home compute with day 6.
12. `UndoContext` registers a global Ctrl+Z handler on the window; `src/app/providers.tsx` now skips it on `/v2` only. Old pages still have it (backlog "Ctrl+Z steals text undo").
13. Row numbers drift after any insert/move/delete: any write that carries a cached row number must re-read first (Phase 1's undo does; the old UI's edits still do not: backend precondition is approved but not built).
14. Tool harness: long foreground `sleep` is blocked; use short sleeps inside bounded loops; run long builds in the background and poll.
15. Hosting handover doc and `README`/`PRODUCT_DOCUMENTATION.md` should be updated at the end of each shipped step (never change a financial value in docs without checking the live sheet).
