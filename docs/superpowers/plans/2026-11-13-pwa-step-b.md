## Task 3: Read-only offline copy of `/api/financials`, with a visible banner

**Files:** `public/sw.js`, `src/components/layout/AppFrame.tsx`, `src/components/layout/Navbar.tsx`, `src/lib/sync-status.ts` (new, pure helpers + tests)

**Interfaces:** `sw.js` separately intercepts `GET /api/financials` only: try the network; on success, clone the response into a dedicated cache entry (overwriting the previous one) and let it through; on failure, serve the cached entry if one exists (otherwise let the failure propagate — no fabricated data). No other `/api/*` route is ever cached or served offline — a queued write is simply refused while offline, with the existing error handling.

The client tracks *its own* "last successful sync" timestamp (not something the SW signals): `AppFrame` records `Date.now()` in state + `localStorage` (`finflow_last_synced`) whenever `useFinancials` resolves successfully *and* `navigator.onLine` is true. `useOnlineStatus()` (new small hook) listens to `window`'s `online`/`offline` events. When offline and the financials query still has data (served from the SW's cache), `AppFrame` shows a dismissible-per-session banner: "Offline — showing a copy saved {relative time}. Reconnect to see the latest." Writes (Log, EMI schedule, any mutation) are disabled offline with a one-line reason, matching the already-decided "offline = read only" rule.

On sign-out (`Navbar`'s `handleLogout`): explicitly `caches.open(...).then(c => c.delete('/api/financials'))` before redirecting to `/login`, so the next person to open the installed app on this device never sees a previous session's numbers.

`src/lib/sync-status.ts` exports `formatSyncedAgo(timestampMs, nowMs): string` (pure, testable: "just now", "3 min ago", "2 hr ago", "yesterday") — used by both the offline banner and Task 4's chip.
