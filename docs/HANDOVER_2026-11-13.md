## 2. How the old UI is built now (post Step A/B — supersedes §6 of the 12 Nov handover)

- **Navigation** (`src/components/layout/nav-items.ts`): **Home** (`/`), **Ledger** (`/expenses`), **Excel** (`/excel`), **Loans** (`/loans`), **Splits** (`/ledger`), **Budget** (`/budget`, new). URLs are unchanged from before; only labels changed. Each item has a `phone: boolean` flag for the bottom bar.
- **Shared frame**: every page under the route group `src/app/(app)/` is wrapped by `AppFrame.tsx`, which owns the single `useFinancials` query, `CycleConfig` (persisted `localStorage` key `finflow_cycle_config`), reference date, and the Log/EMI dialog state — exposed via `useFrame()` (`FrameContext.tsx`). Pages no longer each duplicate ~90 lines of frame.
- **Home** (`/`): `ExecutiveHero` (every sentence built from live data — no hardcoded money text anywhere), a 2-up grid of `BudgetSummaryCard` + `DebtSummaryCard` (compact, link out to `/budget` and `/loans`), `BalanceTimeline`, `SavingsMeter`, `SpendingBreakdown` (categories are links into `/expenses?category=...`; Bhaiya Udhar is excluded from this view only via `homeSpendingCategories()`).
- **Budget** (`/budget`, new): full `ModernBudgetPacing` + `BalanceTimeline`, the detail that used to live in Home's "Budget Burn" tab.
- **Categorization**: `src/lib/computations.ts`'s `computeSpendingCategories` (server/API) and `src/lib/spending-category.ts`'s `categorizeExpenses` (client, row-aware, used for the Ledger's category filter) are kept in parity (tested in `spending-category.test.ts`). Both implement the same Bhaiya-pairing rule.
- **One type system**: sans everywhere except the wordmark/Home hero balance (serif) and the Excel grid/formula bar/row numbers (mono); no wide-tracked caps; nothing under 12px.
- **One Today control**: `TodayFab` (shared component) + `useAnchorInView` hook, used identically on Ledger and Excel; badge text is `Today` when the reference date is actually today, else `As of <date>`.
- **Credits**: blue `#3b82f6` (`--credit` CSS var), never green.
- **44px tap targets**, labelled icon buttons throughout.
- **PWA**: service worker (`public/sw.js`) registered from the root layout (`RegisterSW.tsx`), covers the whole app. Caches only the app shell + the last successful `/api/financials` response; never `/login` or any other `/api/*`. On a genuinely-failed fetch (offline, or just a broken request while "online"), the SW serves the cached copy with an `x-finflow-offline-copy: 1` header; `useFinancials` reads that into `data.offlineCopy`; `AppFrame` derives an offline banner ("Showing saved copy from HH:MM") and a "Synced N min ago" sync chip from `data.offlineCopy`, **not** from `navigator.onLine` (see §6 for why that distinction matters). All mutations (`networkMode: 'always'`) fail fast when actually offline instead of queueing — the app is read-only offline. Install prompt is mobile-only, dismissible, remembered in `localStorage` (`finflow_install_dismissed`).

## 6. Review findings (two whole-branch Opus reviews this session) and how each was ruled

### Step A review
One Critical, two Important, several Minor. All Critical+Important fixed in one TDD pass (`7ed0612`):
- **Critical — `AppFrame.updateConfig` silently dropped fields.** It read a `configRef` updated only in a post-render `useEffect`; `ModernBudgetPacing`'s Apply button called `updateConfig` once per changed field synchronously in the same tick, so every call read the same stale ref and only the last field's change actually took effect in memory (the localStorage merge was fine, which masked the bug until reload). Fixed with a functional `setConfig((prev) => ({ ...prev, ...updates }))`, removing `configRef` entirely.
- **Important — Excel's phone-pinned Description column had no real cap.** `max-sm:min-w-[9rem]` is a floor, not a ceiling; content could still grow past it. Fixed with `max-sm:w-28` on the cell + `max-sm:max-w-[60px] max-sm:truncate` on the inner span.
- **Important — `TableScroller` measured height from the wrong reference point**, collapsing to a 240px floor on pages with summary cards above it (e.g. Splits). Fixed to measure the actually-stuck header + sticky-bar heights, not a scroll-position-dependent calculation.
- **Re-graded from Minor to fixed:** "Today" label showing on non-today rows — judged active misinformation in a finance app, not cosmetic.
- **Deferred (ledgered, not silently dropped):** type-toggle tap-target size in dense tables, dialog focus trap, `FrameValue` not memoized, the pre-existing `auth.ts` hardcoded fallback password (out-of-branch security concern), the hero/computations.ts anchor-rule duplication, Excel's Today-button staleness on filtered views, a few leftover marketing-style copy strings, rose-vs-orange color inconsistency, Excel sub-tab sticky headers/caps.

### Step B review
One Critical, several Important. Fixed in `b3d1227`:
- **Critical — the offline banner was effectively dead code.** TanStack Query's default `networkMode: 'online'` pauses a query entirely once `navigator.onLine` is false, so a genuinely offline session never called `fetch()` and never reached the service worker at all. Separately, the case the feature actually exists for — online but the request is failing (flaky wifi, DNS, server hiccup) — kept `navigator.onLine === true`, so the banner (gated on `!isOnline`) never showed and `lastSyncedAt` (also gated on `navigator.onLine`) wrongly recorded the stale cached response's arrival as "just now," with zero signal to the user that they were looking at old data. Fixed by: `networkMode: 'always'` on the financials query (lets a genuinely offline attempt still reach the SW); the SW marking any cache-served response with `x-finflow-offline-copy: 1`; `useFinancials` reading that header into `data.offlineCopy`; `AppFrame` deriving the banner and gating `lastSyncedAt` off `data.offlineCopy` instead of `navigator.onLine`. Mutations also got `networkMode: 'always'` globally, so offline writes fail fast instead of silently queueing against row numbers that may have shifted.
- Several Important findings about the test suite's own correctness were found and fixed in the same pass — see §7 (these are process lessons, not product bugs, but worth knowing if you touch `test-pwa.cjs` again).
- **Deferred:** iOS splash images, pull-to-refresh gesture, offline-write queueing/conflict precondition — explicitly Step C territory, not built.

## 7. Test inventory and gotchas specific to this session's new code

| Suite | Command | Result |
|---|---|---|
| `npm run audit:ui` | Playwright, 10 consistency rules × every route × phone/laptop | 153/153 |
| `npm run test:unit` | `node:test` via `tsx`, globs `src/v2`, `src/lib`, `src/components` | all pass (includes `computations.test.ts`, `spending-category.test.ts`, `debt-summary.test.ts`, `sheet-row-finder.test.ts`, `sync-status.test.ts`) |

| `npm run integrity` | live, read-only, 6 checks | 6/6, CHECK 5 = 114021 |
| `src/scripts/test-pwa.cjs` | Playwright, PWA-specific, run via `npx tsx` or node directly (it's `.cjs`) | 27/27 |

Gotchas discovered and fixed while building this session's tests (useful if you extend `test-pwa.cjs` or `audit-ui.cjs` again):
- **`Response.clone()` must happen synchronously**, before any async chain touches the response body, or it throws `"Response body is already used"` — this was a real bug in `sw.js`, not just a test issue (see the service-worker code in §2).
- **Playwright's `isVisible({ timeout })` does not wait** — it's an immediate synchronous check and silently ignores the timeout option in this Playwright version. Use `locator.waitFor({ state: 'visible'|'hidden', timeout })` instead (helpers `waitVisible`/`waitHidden` in `test-pwa.cjs`).
- **`ctx.setOffline(true)` + full navigation hits the generic `offline.html` fallback**, not the app's real offline-copy mechanism (no app-shell precache exists for a full reload). To test the real mechanism, stay on an already-open page, go offline, then interact (e.g. click "Sync now").
- A genuinely useful **"lie-fi" scenario** (`navigator.onLine` never toggled, but `ctx.route(/\/api\/financials/, r => r.abort('failed'))`) is what actually proves the Critical fix in §6 — confirmed first, via a standalone diagnostic, that Playwright's route interception does reach `fetch()` calls made from inside a service worker's own fetch handler (not just page-originated fetches).
- Any write-probe test payload must still fail server-side validation (e.g. `amount: 0` → 400) so a test bug can never actually write to the live sheet.
- Navigating to an uncached route while offline destroys the live React app (replaced by the static fallback page); run that check **last** in any offline test sequence, after anything that still needs the real app.
